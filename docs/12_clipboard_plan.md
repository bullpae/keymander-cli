# 클립보드 히스토리 — 다중 버퍼 붙여넣기 설계

> 상태: 계획 (2026-08-08) · 선행 검증: InjectPaste E2E ✅ (docs/11 R3-1) ·
> 남은 전제: 전경창 캡처 (R3-2, 흐름 B에만 필요)

## 0. 설계 원칙 — keymander 문법의 연장

nav 레이어에는 이미 vim의 복사/붙여넣기 문법이 있다:

- `LAlt+Y` = 줄 복사 (yank)
- `LAlt+P` = 붙여넣기 (paste)

클립보드 확장은 새 UI 문법을 발명하지 않는다. **기존 Y/P를 단일 버퍼에서
다중 버퍼로 확장**하는 것이 전부다. 손이 홈로우를 떠나지 않고, 마우스는
등장하지 않으며, 자주 쓰는 경로일수록 UI가 없어진다.

두 개의 사용 흐름이 서로 다른 keymander 정체성을 계승한다:

| 흐름 | 계승하는 정체성 | UI | 대상 |
|---|---|---|---|
| A. 즉시 붙여넣기 | **레이어** (VIA/QMK 홀드) | 없음 | 최근 1–9번 (근육 기억) |
| B. 탐색 붙여넣기 | **런처** (검색 우선) | alt+space | 히스토리 전체 (기억 밖) |

## 1. 저장 모델 — 몇 개를 어떻게 저장하나

```
핫 슬롯   1..9          ← 레이어로 즉시 접근 (최신=1, 근육 기억의 한계가 9)
히스토리  50 (설정 가능) ← 런처 검색으로 접근, FIFO 링
레지스터  a–z 26칸       ← v2: 명시적 고정 슬롯 (vim named register)
```

- **핫 슬롯 9개**: 근육 기억으로 "n번째 전에 복사한 것"을 기억하는 실용적
  상한. 10 이상은 아무도 위치로 기억하지 못한다 — 그건 검색의 영역.
- **히스토리 50개** (`clipboard.history_size`, 0=기능 끔): 검색으로 찾는
  영역. 링 버퍼라 오래된 것부터 밀려난다.
- **레지스터(v2)**: 히스토리는 흘러가지만 레지스터는 사용자가 명시적으로
  고정한다("이 계좌번호는 `a`에"). vim `"a`–`"z`의 계승. 디스크 저장(0600).
- 같은 내용 재복사 = 중복 생성 없이 맨 앞으로 이동(dedupe).
- v1은 **텍스트만**. 이미지/파일은 v2.

### 프라이버시 (키 훅 프로그램의 의무)

- 히스토리는 **메모리에만** 산다. 디스크 비저장이 기본
  (`clipboard.persist = false`). 켜면 0600 + 데이터 디렉터리 0700.
- **비밀번호 제외**: macOS `org.nspasteboard.ConcealedType`,
  Windows `CF_CLIPBOARD_VIEWER_IGNORE` / `ExcludeClipboardContentFromMonitorProcessing`
  마크가 있는 항목은 수집하지 않는다 (1Password 등 비번 관리자 관례).
- 1MB 초과 텍스트는 수집 제외(메모리 보호). `clipboard.max_age_minutes`
  옵션으로 오래된 항목 자동 소거 가능(기본 off).
- 히스토리 내용은 로그에 절대 남기지 않는다 (기존 keycode 불로깅 원칙과 동일).

## 2. 수집 — 사용자는 아무것도 배우지 않는다

복사는 평소처럼 한다 (`Cmd+C`, nav `Y`, 어디서든). 데몬이 상주하며 수집한다:

- macOS: `NSPasteboard.changeCount` 폴링 (250ms) — ✅ 구현. 값이 바뀔 때만
  get_text 호출(경합·비용 최소화). `ConcealedType` 마크 항목은 수집 제외 ✅
- Windows: `AddClipboardFormatListener` (이벤트 기반, 폴링 없음)

히스토리가 데몬에 사는 이유(docs/11 R3 배경): 클립보드 감시는 상주
프로세스만 가능하고, 상주 프로세스는 데몬뿐이다.

## 3. 흐름 A — 즉시 붙여넣기 (레이어, UI 없음)

**`LAlt` 홀드 + `1..9` = n번째 최근 항목을 지금 포커스된 앱에 붙여넣기.**

```
"아까 URL 복사하고, 그 다음 제목 복사했지" 
→ 에디터에서 LAlt+2 (URL), LAlt+1 (제목). 끝. 창 전환 없음, UI 없음.
```

- `LAlt+P`는 기존대로 최신 붙여넣기(= `LAlt+1`과 동일)로 남는다 — 기존
  근육 기억 보존.
- 포커스가 이미 대상 앱에 있으므로 **전경창 캡처(R3-2)가 필요 없다** —
  이 흐름은 지금 검증된 능력(InjectPaste)만으로 구현 가능.
- 동작: 데몬이 시스템 클립보드를 슬롯 내용으로 교체 → `Cmd+V`/`Ctrl+V`
  주입 → 300ms 후 원래 클립보드 복원 (클립보드 관리자 표준 기법.
  주입 이벤트는 MAGIC_USER_DATA로 자체 탭 재처리 방지 — 기존 인프라).
- 구현: 엔진에 `BindAction::ClipPaste(n)` 추가, 매핑 문법 `"clip:2"`.

**트레이드오프 (구현 시 결정)**: `clip:N`을 **기본 프리셋에 넣지 않기로 했다.**
넣으면 (a) 히스토리가 opt-in(기본 off)인데도 Alt+숫자를 가로채고, (b) Windows
브라우저의 Alt+숫자 탭 전환과 충돌한다. 대신 히스토리를 켤 때 사용자가 원하는
슬롯만 직접 매핑한다 (docs/06 §4.7). opt-in 기능에는 opt-in 매핑이 맞다.
(macOS는 Cmd+숫자가 탭 전환이라 Alt+숫자가 비어 충돌 없음.)

**구현 상태 (2026-08-08, P1 완료)**: 데몬 수집(arboard 폴링 250ms · dedup ·
1MB 상한 · 메모리 전용) + `BindAction::ClipPaste(n)` + 스왑→주입→복원 구현.
E2E 검증: 표식 3개 순차 복사 → `clip-test --slot 2`로 두 번째 항목 정확히
붙여넣기 + 원래 클립보드 복원 확인. 남은 것: Concealed 마크 제외(P1.1,
NSPasteboard FFI), NSPasteboard changeCount 기반 감시(현재는 get_text 폴링).

인체공학 노트: LAlt(왼엄지)+왼손 숫자(1–5)는 "홀드 손 ≠ 조작 손" 원칙에서
벗어나지만, "n번째"라는 니모닉 가치가 원칙을 이긴다고 판단. 오른손 숫자
(6–9)는 원칙에도 부합.

## 4. 흐름 B — 탐색 붙여넣기 (런처, 검색 우선)

**`alt+space` → `;검색어`** — 히스토리 50개를 퍼지 검색(한글 포함, 기존
Nucleo 엔진 재사용). 각 항목은 첫 줄 미리보기 + 복사 시각 + 출처 앱(v2).

```
;계좌      → "우리은행 1002-..." 항목 → Enter → 이전 앱에 붙여넣기
```

- **`Enter` = 이전 앱에 붙여넣기** (기본 액션 — 이게 이 기능의 존재 이유).
  런처가 포커스를 뺏기 전 앱을 데몬이 기억했다가(→ **R3-2 전경창 캡처**,
  이 흐름의 유일한 전제) 그 앱을 활성화하고 주입한다.
- `Cmd+Enter` = 클립보드에 복사만 (붙여넣기는 내가 알아서).
- prefix는 `;` — 한 글자(빈도 높은 기능은 짧게), 기존 문법(`:calc`,
  `:e`, `!`, `@gpt`)과 충돌 없음. alias `:clip`, `:v` 병행 등록
  (query_prefix.rs COMMANDS — 단일 진실 소스).
- nav 레이어 `V` = 런처를 `;` 프리필로 실행 (`launch:kmd-desktop` 확장,
  홈로우에서 히스토리 탐색까지 두 키). — Y(yank)·P(paste) 옆의 V, vim의
  visual 선택 니모닉.

## 5. IPC 표면 (분리 구조 유지 — docs/11 R3 하이브리드 원칙)

클립보드는 "능력형 확장"이다: 상주 상태(히스토리)와 주입(붙여넣기)이 모두
데몬에 있고, UI(런처)는 IPC로 조회·실행한다.

```
Request::ClipHistory { query, limit }      → 데몬 히스토리 검색 (내용은 응답에만)
Request::ClipPaste { id, target: Prev|Focus } → 클립보드 교체+주입(+복원)
Request::InjectPaste                        → (기존, R3-1) ClipPaste의 기반
```

`ExtensionAction`에는 `PasteToPrevious(String)`가 추가된다 — 순수형 확장
(calc/emoji)도 "결과를 이전 앱에 바로 붙여넣기"를 쓸 수 있게 되는 부수 효과
(예: `:calc 3*7` → Enter가 복사가 아니라 **붙여넣기**).

## 6. 구현 순서 (각 단계가 독립적으로 유용)

1. **P1 — 수집 + 흐름 A** (R3-2 불필요, 지금 가능): 데몬 클립보드 감시 링
   버퍼 + `BindAction::ClipPaste(n)` + 클립보드 스왑·복원. 이것만으로
   "LAlt+2 = 두 번 전 복사 붙여넣기"가 동작한다.
2. **P2 — R3-2 전경창 캡처**: 데몬 Launch 경로에서 전경 앱 스냅샷
   (autopilot의 창 추적 재사용).
3. **P3 — 흐름 B**: `;` prefix + `ClipHistory`/`ClipPaste` IPC + 런처 통합
   + nav `V`.
4. **v2**: 레지스터(a–z), 이미지, 출처 앱 표시, `:calc` 결과 직접 붙여넣기.

## 7. 검증 계획

- 흐름 A: 표식 3개 순차 복사 → TextEdit에서 `clip:2` 주입 → 두 번째 표식
  확인 + 원래 클립보드 복원 확인 (InjectPaste E2E 확장).
- 프라이버시: ConcealedType 마크 항목이 히스토리에 안 들어오는지,
  히스토리가 디스크에 안 남는지(`clipboard.persist=false`에서 파일 부재).
- 흐름 B: 런처 → `;` 검색 → Enter → 이전 앱 붙여넣기 E2E.

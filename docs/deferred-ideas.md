# 보류 항목 아이디어 목록

> 이 문서는 v0.3 로드맵 검토 과정에서 **좋은 아이디어이나 현 단계에서는 보류**로 판단된 기능을 정리한 것입니다.
> 향후 필요 시 참고하여 구현 여부를 재검토할 수 있습니다.

---

## 1. Intent Router (의도 라우터)

**개요**: 사용자 입력을 자연어 수준에서 분석하여 적합한 명령/서비스로 자동 라우팅.

**보류 사유**:
- 현재 `@prefix` + `:command` 체계로 충분히 직관적
- 자연어 분석은 외부 LLM 의존 또는 로컬 모델 필요 → 바이너리 크기/속도 이슈
- "키보드 런처"의 명시적/결정론적 특성과 상충

**향후 검토 조건**:
- 사용자가 prefix를 외우지 못하는 UX 피드백이 축적될 때
- 로컬 경량 분류 모델(예: onnx micro model)이 현실적일 때

---

## 2. Flow Command (멀티스텝 워크플로우)

**개요**: 여러 명령을 파이프라인으로 연결 (예: `클립보드 → 번역 → 복사`).

**보류 사유**:
- 현재 `:t` (Quick Transform)이 단일 스텝 워크플로우 역할을 대신함
- 멀티스텝 파이프라인은 설계 복잡도 대비 사용 빈도가 낮을 것으로 예상
- Keymander의 핵심은 "빠른 단발 실행"이지 "복잡한 자동화"가 아님

**향후 검토 조건**:
- `:t` 사용 패턴 분석 후, 2단계 이상 체인이 자주 필요하다는 피드백
- 쉘 스크립트/AutoHotKey와의 차별점이 명확해질 때

---

## 3. Plugin Marketplace / 플러그인 마켓플레이스

**개요**: 커뮤니티가 만든 플러그인을 설치/관리하는 시스템.

**보류 사유**:
- 현재 사용자 기반이 충분하지 않음 → 마켓플레이스 유지 비용 > 효과
- 내장 기능(web, spell, translate, prompt)으로 핵심 니즈 충족
- 플러그인 보안 검증 체계 필요

**향후 검토 조건**:
- 사용자 수가 유의미하게 증가하고, 커스텀 기능 요구가 늘어날 때
- 단순한 "config 기반 확장"(custom web services)이 부족해질 때

---

## 4. AI-Powered Summarize / 자동 요약

**개요**: 클립보드나 선택된 텍스트를 LLM으로 요약.

**보류 사유**:
- API 키 관리, 비용 발생 → 무료/오프라인 원칙과 상충
- 현재 `@ll` 멀티 프롬프팅으로 LLM 활용 가능 (수동이지만 충분)
- 브라우저 기반 서비스 접근이 이미 가능

**향후 검토 조건**:
- 로컬 LLM(예: llama.cpp) 통합이 실용적이 될 때
- 사용자가 명시적으로 API 키를 설정하는 opt-in 모델

---

## 5. Snippet Manager / 코드 스니펫 관리

**개요**: 자주 사용하는 코드/텍스트 스니펫을 저장하고 빠르게 검색/붙여넣기.

**보류 사유**:
- `:prompt` 템플릿이 일부 역할을 대신함
- 전용 스니펫 매니저(예: Alfred snippets)와의 차별점 부족
- 클립보드 히스토리와 겹치는 영역

**향후 검토 조건**:
- `:prompt`의 한계가 드러날 때 (예: 바이너리 데이터, 멀티라인 스니펫)
- 개발자 중심 사용 패턴에서 빈번한 요구가 있을 때

---

## 6. Window Manager / 윈도우 관리

**개요**: 키보드로 윈도우 배치, 리사이즈, 포커스 전환.

**보류 사유**:
- OS별 API가 매우 다름 (Win32, Cocoa, X11/Wayland)
- PowerToys FancyZones, Rectangle 등 기존 도구가 잘 동작
- Keymander의 핵심 영역(런처)에서 벗어남

**향후 검토 조건**:
- Kanata 키맵핑 통합이 성숙한 후, 키보드 중심 워크플로우의 자연스러운 확장으로
- Windows 전용으로 한정하여 Win32 API 직접 활용 시

---

## 7. Bookmark / 즐겨찾기 시스템

**개요**: 자주 사용하는 파일/URL/명령을 즐겨찾기로 등록.

**보류 사유**:
- 히스토리 boost가 이미 자주 사용하는 항목을 상위에 표시
- 중복 기능 우려

**향후 검토 조건**:
- 히스토리 boost로 충분하지 않다는 피드백
- "고정 즐겨찾기" vs "자동 학습"의 차이가 유의미할 때
